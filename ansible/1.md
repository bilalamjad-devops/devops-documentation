## Core Ansible Concepts Covered

*   **Control Node (Master Server):** The central engine where Ansible is installed and from which automation scripts are triggered.
*   **Managed Nodes (Host/Target Servers):** Remote infrastructure configurations (e.g., Linux instances) managed via Ansible. No agent installation required on target hosts (Agentless architecture).
*   **Inventory:** A configuration file (`hosts`) containing structured tracking parameters (IPs, groups, patterns) of all target nodes.
*   **Modules:** Discrete atomic units of execution (small tasks) packaged by Ansible (e.g., package installation, file operations, process handlers).
*   **Ad-Hoc Commands:** Quick operational commands executed directly on the terminal via the core binary tool without writing full automated workflows.

---

## Step-by-Step Implementation

### Step 1: Install Ansible on the Control Node (Master Server)
Update the core system package repositories and fetch the stable version of the Ansible engine:

```bash
sudo apt update
sudo apt install ansible -y

```

### Step 2: Configure SSH Authentication Assets

Ansible communicates securely with target instances using standard asymmetric SSH cryptography.

```bash
# Navigate to the local user SSH home layout
cd ~/.ssh

# Create and insert the private key securely (.pem key retrieved from AWS console)
vim ansible_key

# Paste key, exit and save using standard editor rules (Esc, :wq!)

```

Set structural Linux access privileges for security validation:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/ansible_key

```

*Verification test to ensure seamless multi-node jump:*

```bash
sudo ssh -i ~/.ssh/ansible_key ubuntu@<TARGET_PUBLIC_IP>
exit

```

### Step 3: Construct a Decoupled Dynamic Inventory File

Instead of leveraging global configurations under `/etc/ansible/hosts`, create a localized environment execution pattern:

```bash
mkdir ~/ansible && cd ~/ansible
vim hosts

```

Add the target nodes metadata variables inside the inventory layout configuration:

```ini
[servers]
server1 ansible_host=publicip1 
server2 ansible_host=publicip2 
server3 ansible_host=publicip3 

[all:vars]
ansible_python_interpreter=/usr/bin/python3 

```

Verify if the current schema successfully maps out with core parsers:

```bash
ansible-inventory --list -y -i ~/ansible/hosts

```

---

## Automation Ad-Hoc Executions & Monitoring

### 1. ICMP/Network Ping Automation Module Test

To double-check absolute connectivity across all inventory endpoints safely:

```bash
ansible all -m ping -i ~/ansible/hosts --private-key=~/.ssh/ansible_key

```

### 2. Live Fleet Ram/Memory Audit Output

Execute interactive shells across nodes to process current active memory performance metrics (`free -h`):

```bash
ansible all -a "free -h" -i ~/ansible/hosts --private-key=~/.ssh/ansible_key

```

### 3. High Availability Systems Uptime Check

Monitor target computing nodes overall performance timeline logs seamlessly:

```bash
ansible all -a "uptime" -i ~/ansible/hosts --private-key=~/.ssh/ansible_key

```
