


# 🚀 Automating Deployments with Ansible Playbooks and GitHub Actions CI/CD

## 🌟 Introduction
In DevOps, automation is the key to speed and reliability. While **Ansible** helps us configure and manage servers, **GitHub Actions** provides a powerful CI/CD engine to automate builds and deployments. Combining the two creates a seamless workflow: every time code is pushed to GitHub, Ansible playbooks can automatically configure servers and deploy applications.

---

## ⚙️ Problem Statement
Traditionally, deploying applications to servers required manual steps:
- Logging into servers via SSH  
- Running configuration commands  
- Copying files and restarting services  

This process is slow, error‑prone, and doesn’t scale. We need a way to **automate deployments** so that every commit can trigger a reliable pipeline.

---

## 💡 Solution
By integrating **Ansible Playbooks** with **GitHub Actions**, we can:
- Define server tasks in Ansible (install packages, configure services, deploy apps).  
- Trigger these playbooks automatically whenever code changes are pushed.  
- Ensure deployments are consistent across environments (dev, staging, production).  

---

## 🧪 Steps to Build the Pipeline

### 🔹 1. Write an Ansible Playbook
Example: `deploy.yml`
```yaml
- hosts: servers
  become: yes
  tasks:
    - name: Install Nginx
      apt:
        name: nginx
        state: present
        update_cache: yes

    - name: Copy application files
      copy:
        src: ./app/
        dest: /var/www/html/

    - name: Restart Nginx
      service:
        name: nginx
        state: restarted
```

### 🔹 2. Configure Inventory
`hosts.ini`
```ini
[servers]
server1 ansible_host=<public_ip_1> ansible_user=ubuntu
server2 ansible_host=<public_ip_2> ansible_user=ubuntu
```

### 🔹 3. Create GitHub Actions Workflow
`.github/workflows/deploy.yml`
```yaml
name: CI/CD Pipeline

on:
  push:
    branches: [ "main" ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v3

      - name: Set up Ansible
        run: sudo apt-get install ansible -y

      - name: Run Playbook
        run: ansible-playbook -i hosts.ini deploy.yml --private-key ~/.ssh/ansible_key
```

### 🔹 4. Secure SSH Keys
- Store your private key in GitHub **Secrets**.  
- Reference it in the workflow to connect securely to servers.  

---

## 🧭 Conclusion
By combining **Ansible Playbooks** with **GitHub Actions**, you’ve built a fully automated CI/CD pipeline. Every push to GitHub now triggers a deployment, ensuring your servers are always up to date. This integration reduces manual effort, improves reliability, and brings you closer to true DevOps automation.
