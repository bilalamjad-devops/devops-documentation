# ⚙️ Ansible Lab 2: Using Inventory + Playbooks

## 🌟 Introduction
In the previous lab, we learned how to use Ansible with just an **inventory file** and ad‑hoc commands. That was a great start, but running commands one by one quickly becomes repetitive. The next step is to use **playbooks** — YAML files that define tasks in a structured, reusable way.  

This lab shows how to combine the **inventory file** with a **playbook** to automate tasks across multiple servers.

---

## 🧩 Problem Statement
Ad‑hoc commands are useful for quick checks, but they don’t scale well. For example, installing Nginx or configuring a service across multiple servers requires repeating commands. We need a way to:
- Define tasks once  
- Reuse them across environments  
- Keep automation consistent  

---

## 💡 Solution
Ansible **playbooks** solve this problem. A playbook is a YAML file that describes tasks (modules) to run on hosts defined in the inventory. By combining inventory + playbook, we can automate multi‑step processes with a single command.

---

## 🧪 Steps

### Step 1: Inventory File
Create `hosts` file:
```ini
[servers]
server1 ansible_host=<public_ip_1> ansible_user=ubuntu
server2 ansible_host=<public_ip_2> ansible_user=ubuntu
server3 ansible_host=<public_ip_3> ansible_user=ubuntu

[all:vars]
ansible_python_interpreter=/usr/bin/python3
```

### Step 2: Write a Playbook
Create `install_nginx.yml`:
```yaml
- hosts: servers
  become: yes
  tasks:
    - name: Update apt cache
      apt:
        update_cache: yes

    - name: Install Nginx
      apt:
        name: nginx
        state: present

    - name: Start Nginx service
      service:
        name: nginx
        state: started
```

### Step 3: Run the Playbook
```bash
ansible-playbook -i hosts install_nginx.yml --private-key ~/.ssh/ansible_key
```

---

## 🔐 Verify
Check if Nginx is running:
```bash
ansible all -a "systemctl status nginx" -i hosts --private-key ~/.ssh/ansible_key
```

## 🧭 Conclusion
With this lab, you’ve moved from **ad‑hoc commands** to **structured automation**. The inventory file defines your servers, and the playbook defines tasks. Together, they make deployments repeatable and reliable.
